## 1. 원칙

1. **형제 서비스처럼 보인다.** 레이아웃·글꼴·여백은 PLUS 화면과 같게 두고, 색만 ON의 Mint + Lime으로 바꾼다. 기본 버튼(primary)은 PLUS console과 같은 Mint 계열(한 단계 짙게)이고, 강조를 주는 포인트는 Lime 500(`#C3E89E`)이다.
2. **무료와 유료를 첫눈에 구분한다** (PRD 8.1). 받기와 구매의 버튼 색이 다르고, 문구도 다르다.
3. **파스텔 위 글자는 Navy.** 밝은 Lime·Mint 면에 흰 글자를 올리지 않는다. 흰 글자는 Mint·Lime 800 이상, Navy 위에만 쓴다.
4. **색만으로 상태를 말하지 않는다.** 쿠폰·주문 상태는 항상 색과 문구를 함께 보여 준다.
5. **토큰으로만 칠한다.** 컴포넌트는 hex 값을 직접 쓰지 않고 `var(--…)`를 참조한다. 인라인 스타일은 쓰지 않는다 (저장소 규칙).

### 3.1 시그니처

| 토큰              | 값                                                  | 쓰는 곳                                                              |
| ----------------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| `--on-gradient`   | `linear-gradient(135deg, #7FE7D8 0%, #C3E89E 100%)` | [무료로 받기], 관리자 로그인 버튼, 강조 면                           |
| `--on-button-neg` | `linear-gradient(135deg, #1E7B76 0%, #2F8059 100%)` | 어두운 강조 면 (흰 글자)                                             |
| `--on-point`      | `#C3E89E` Lime 500                                  | 포인트: "무료" 배지·핀 말풍선, 다크 사이드바 활성 글자, Navy 위 강조 |
| `--on-sub`        | `#7FE7D8` Mint 500                                  | 그라데이션 시작색, 보조 틴트                                         |

그라데이션 위 글자는 `#10162E`(text-primary)다. 대비는 Mint 쪽 12.18:1, Lime 쪽 13.06:1이다.

**포인트와 서브를 맞바꿨다 (2026-10-20, 시험).** 처음에는 Lime이 포인트, Mint가 서브였다. 지금은 기본 버튼·선택 상태·"무료" 배지·탭바·다크 사이드바 활성·포커스·그래프처럼 역할로 칠하는 자리를 Mint가 맡고, Lime은 서브로 돌렸다. ON 그라데이션도 Mint → Lime으로 뒤집었고, 로고·파비콘의 ON 글자도 같은 방향으로 바꿨다 (파비콘 픽셀은 모양·투명도를 두고 색만 Lime·Mint 사이에서 뒤집었다). 쿠핀 컬러 시스템(all.html)의 ON 시그니처는 Lime → Mint라 그와 방향이 반대다. 기본 버튼 Mint 800(`#1E7B76`)은 PLUS console의 Mint 800(`#2A7D72`, console hover 색)과 거의 같은 색이라 (OKLab 차이 0.012) PLUS 화면과 구분이 약해진다.

**포인트 색은 `#C3E89E` (2026-10-20).** primary(기본 버튼 Mint 800, 선택 상태, 포커스)는 그대로 두고, 화면에서 강조를 주는 자리만 Lime 500을 쓴다: "무료" 배지와 지도 핀 "무료" 말풍선, 다크 사이드바 활성·hover 글자, Navy 토스트의 동작 버튼. Lime 500은 흰 바탕 대비가 1.37:1이라 흰 바탕 위 글자·선으로는 쓰지 않고, 진한 글자(`#10162E`, 13.06:1)를 올리는 면이나 어두운 면(사이드바 12.19:1, Navy 9.42:1) 위에만 쓴다.

### 3.2 코어 스케일

ON이 직접 만든 스케일이다 (2026-10-20, 사수 확인: all.html 06장 컬러 스케일 대신 시그니처에 어울리는 값으로 정해도 된다). 500은 시그니처 그대로다.

**만든 방법.** 사람 눈에 고르게 느껴지는 OKLCH 색 공간에서 500을 기준으로 명도를 단계별로 내렸다. all.html 스케일은 어두운 단계에서도 Lime의 노란빛 색상각(130°)을 그대로 두어 700~900이 올리브·카키로 탁해졌다. 새 스케일은 어두워질수록 색상각을 Lime은 초록 쪽(600~900에서 149° → 165°), Mint는 청록 쪽(185° → 193°)으로 조금씩 돌려 맑은 잎색으로 둔다. Lime 800이 Mint 쪽으로 기울어 있어 ON 그라데이션의 두 끝 사이에 놓인다.

**Mint를 섞었다 (2026-10-20).** Lime에 Mint 느낌을 더해 달라는 피드백으로, 500을 뺀 Lime 각 단계에 같은 단계의 Mint를 OKLab에서 35% 섞었다. 색상각이 밝은 단계는 128~130°에서 142~147°로, 어두운 단계는 134~153°에서 149~165°로 옮겨 갔다. 500은 ON 시그니처라 그라데이션·로고·파비콘과 함께 그대로 두었고, 그래서 스케일에서 500만 조금 더 노란빛이다. 흰 글자 대비는 섞은 뒤 조금 올랐다 (800: 4.72 → 4.82:1).

### 3.3 primary 매핑과 PLUS와 다른 점

PLUS console은 흰 글자를 올리는 솔리드 색으로 Mint 700(`#3FA597`)을 쓴다. 흰 글자 대비는 2.98:1로 WCAG AA에 못 미친다. ON은 PRD 8.4에서 WCAG 2.1 AA를 목표로 하므로 **한 단계 짙은 Mint 800**을 쓴다. 매핑 방식은 console과 같다.

| 토큰                           | ON 값                                                                                   | PLUS console 값    | 흰 글자 대비 |
| ------------------------------ | --------------------------------------------------------------------------------------- | ------------------ | ------------ |
| `--primary-color`              | `#1E7B76` Mint 800                                                                      | `#3FA597` Mint 700 | 5.06:1       |
| `--primary-hovered-color`      | `#0A4F4E` Mint 900                                                                      | `#2A7D72` Mint 800 | 9.37:1       |
| `--primary-5` ~ `--primary-90` | Mint 50 ~ 900 (5→50, 10→100, 20→200, 30→300, 40·50→500, 60→600, 70→700, 80→800, 90→900) | Mint 같은 방식     |              |

Mint 700(`#38A299`, 3.09:1)과 Lime 700(`#5CAB75`, 2.79:1)은 흰 글자 대비가 모자라 글자 배경으로 쓰지 않는다. 아이콘·그래프 선·테두리에만 쓴다.

### 3.8 카테고리 팔레트

카테고리 색은 운영자가 고르지 않고 자동으로 붙는다 (PRD 6.8). 만든 순서대로 아래 8색을 돌려 쓴다.

8색은 OKLCH 명도 0.65, 채도 0.12로 모두 같고 색상각만 고르게 나눴다 (청록만 sRGB에서 낼 수 있는 채도가 0.111이라 그 값을 쓴다). 그래서 지도 위에서 어느 한 업종만 튀지 않고 한 묶음으로 보인다. 흰 아이콘 대비는 모두 3.08:1 이상이다 (그래픽 기준 3:1). 2번 청록은 기본 버튼(Mint 800)과 색상각이 거의 같고 한 단계 밝다. 선택된 칩 테두리(Mint 700)와는 거의 같은 색이다 (OKLab 차이 0.018).

| 순서 | 토큰           | 값        | 색상각 | 흰 아이콘 대비 |
| ---- | -------------- | --------- | ------ | -------------- |
| 1    | `--cat-green`  | `#57A364` | 148°   | 3.08:1         |
| 2    | `--cat-teal`   | `#00A4A1` | 192°   | 3.08:1         |
| 3    | `--cat-sky`    | `#3D98D1` | 240°   | 3.18:1         |
| 4    | `--cat-indigo` | `#8485D6` | 282°   | 3.33:1         |
| 5    | `--cat-violet` | `#AD77BE` | 318°   | 3.41:1         |
| 6    | `--cat-rose`   | `#C86E92` | 356°   | 3.44:1         |
| 7    | `--cat-coral`  | `#CE7164` | 29°    | 3.40:1         |
| 8    | `--cat-amber`  | `#C37D39` | 62°    | 3.33:1         |

**톤 업 (2026-10-20).** 처음 값(명도 0.585)이 Lime·Mint·Navy 옆에서 유난히 무거워 보인다는 피드백으로, 흰 아이콘 대비 3:1을 지키는 한계인 명도 0.65까지 올렸다. 이 색을 함께 쓰는 그래프 취소·환불 선(rose, 3.10), 내 위치 점(sky, 7.5), 대시보드 타일 아이콘(sky·indigo, 8.2)도 같이 바뀐다. 대시보드 타일 아이콘은 옅은 타일 배경 위 대비가 2.80:1(sky), 2.91:1(indigo)로 그래픽 기준 3:1에 못 미친다.

카테고리가 8개를 넘으면 1번부터 다시 쓴다. 칩 안에서는 이 색을 아이콘 원에만 쓰고, 칩 글자는 중립색으로 둔다.

### 3.11 로고 (결정 2026-10-20)

PLUS 콘솔 로고(`apps/plus-console-web/src/assets/images/logo.svg`, `logo-black.svg`, `favicon.ico`)와 같은 구조로 만들었다. 파일은 `docs/on/assets/`에 있고, ON 앱을 만들면 앱 `src/assets/images/`로 옮긴다.

| 파일             | 쓰는 곳                                                 | 구성                                                                                      |
| ---------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `logo.svg`       | 어두운 배경: 관리자 사이드바(`.custom-sider_logo`)      | 쿠핀 심볼·coupin 글자는 마스터 4색 그라데이션 그대로, ON 글자는 Mint → Lime               |

| `favicon.ico`    | 브라우저 탭 (16×16)                                     | PLUS favicon 픽셀의 모양·투명도를 그대로 두고 색만 Mint → Sky 자리를 Mint → Lime으로 옮김 |

- **이전 로고 (Lime → Mint).** 포인트·서브를 맞바꾸기 전의 로고는 지우지 않고 이름 끝에 `-lime-mint`를 붙여 남겼다: `logo-lime-mint.svg`, `logo-black-lime-mint.svg`, `favicon-lime-mint.ico`, `favicon-lime-mint.svg`. 쿠핀 컬러 시스템(all.html)의 ON 시그니처 방향과 같은 쪽이다.
- **만든 방법.** PLUS 로고에서 서비스 이름(Plus) 경로 4개와 그 그라데이션만 지우고, 같은 자리에 ON을 넣었다. ON 글자는 Pretendard Regular 글리프 윤곽을 Plus의 글자 높이(35.6)와 기준선(51.64)에 맞춰 경로로 바꿨다. Pretendard Regular의 획 두께 비율은 Plus 글자와 3% 안에서 같다. 쿠핀 심볼과 coupin 글자 경로는 원본 그대로다.

- **앱 아이콘**(스토어용 1024px 등)은 아직 없다. `favicon.svg`를 출발점으로 앱 출시 준비 때 만든다.

### 4.4 기기 글자 크기 대응 (고객 웹)

고객 웹은 모바일이 주 사용 환경이라, 기본 크기를 키우는 것보다 사용자가 키운 글자 크기를 따르는 것이 더 중요하다.

- **화면 확대를 막지 않는다.** viewport에 `user-scalable=no`, `maximum-scale`을 쓰지 않는다. 입력칸 자동 확대는 막는 대신 입력칸 글자를 16px로 두어 피한다 (7.2).
- **글자가 든 요소는 높이를 고정하지 않는다.** 버튼·칩·목록 행은 `height` 대신 `min-height`로 잡아, 글자가 커져도 잘리거나 겹치지 않게 한다. 높이 표(7장)의 값은 기본 글자 크기일 때의 최소 높이다.
- **글자를 200%까지 키워도 내용이 잘리지 않는다** (WCAG 2.1 1.4.4). 한 줄 말줄임을 쓰는 곳(가게 카드 한 줄 소개 등)은 상세 화면에서 전문을 볼 수 있어야 한다.
- **앱 웹뷰도 같은 기준을 따른다.** 시스템 글자 크기 설정이 웹뷰에 반영되는지(Android `textZoom`, iOS 동적 글자 크기)는 Flutter 웹뷰 셸을 만들 때 함께 확인한다.

### 7.7 아이콘 (고객 웹·관리자 공통)

아이콘은 고객 웹과 관리자 웹 모두 한 가지 방식으로 일관되게 쓴다.

**지금 저장소 상황 (조사).** console·admin·audit 웹은 `@ant-design/icons`(5.6)를 주로 쓰지만, 공용 `@coupin/cims-icons`(손으로 짠 컴포넌트 5개, 색 고정), cims-ui `SiderIcon.tsx`(사이드바 7개), 코드 안 직접 그린 SVG, CSS 안 SVG(약 100곳)가 섞여 있다. 소비자 화면인 plus-qr-web에는 아이콘 체계가 없다. 다른 아이콘 라이브러리(lucide 등)와 svgr 설정은 없다.

**규칙**

1. **출처는 하나.** 고객 웹과 관리자 웹 모두 `@ant-design/icons`만 쓴다. 이 패키지는 antd 컴포넌트 없이도 단독으로 쓸 수 있어, antd를 쓰지 않는 고객 웹에도 들일 수 있다. 새 아이콘 라이브러리를 더하지 않는다.
2. **Outlined만 쓴다.** Filled를 섞지 않는다. `UserFilled`, `CoffeeFilled`, `ScissorFilled`처럼 Filled가 없는 아이콘이 있어서, 섞으면 오히려 들쭉날쭉해진다. 탭바 같은 선택 상태는 채움이 아니라 **색**으로 표시한다 (활성 Mint 800, 비활성 `--gray-80`). 예외는 관리자 사이드바 메뉴 그룹 하나로, PLUS 사이드바와 같은 채움형을 쓴다 (아래 관리자 웹).
3. **크기는 세 단계.** 16px(글자 옆, 칩 안), 20px(목록 행, 버튼 안, 카테고리 원 안), 24px(탭바, 헤더 버튼). 빈 상태 그림만 64px.
4. **색은 `currentColor`.** 아이콘에 hex를 쓰지 않고, 감싼 요소의 글자색 토큰을 따른다.
5. **antd에 없으면 직접 그린다.** antd 규격(`viewBox="64 64 896 896"`, 같은 선 두께)으로 그리고 `<Icon component={...} />`로 감싼다. console 사이드바의 `SiderIcon.tsx` + `@ant-design/icons` `Icon` 방식과 같다. CSS 안 data URI SVG는 새로 만들지 않는다.
6. **운영자가 올린 카테고리 아이콘은 예외.** PRD 6.8대로 운영자가 PNG·SVG를 올리면 배경을 지운 흰 실루엣으로 쓴다.
7. **접근성.** 장식 아이콘은 `aria-hidden`, 아이콘만 있는 버튼(X, ←, 내 위치)에는 `aria-label`을 단다.

## 9. 움직임

| 토큰              | 값                                   | 쓰는 곳                       | 근거              |
| ----------------- | ------------------------------------ | ----------------------------- | ----------------- |
| `--motion-fast`   | 0.2s ease                            | hover, 색 바뀜, 화살표 회전   | console 전반      |
| `--motion-layout` | 0.25s ease-in-out                    | 관리자 사이드바 열고 닫기     | `base.css`        |
| `--motion-screen` | 0.28s cubic-bezier(0.32, 0.72, 0, 1) | 모달·시트 올라옴, push 들어옴 | ON 신규 (PRD 8.5) |

- `@media (prefers-reduced-motion: reduce)`이면 전환과 스켈레톤 반복을 모두 끈다 (PRD 8.5, IA R10).

## 10. 접근성

| 조합                                | 대비             | 판정                        |
| ----------------------------------- | ---------------- | --------------------------- |
| `--text-primary` / `--surface-base` | 17.85:1          | AA                          |
| 흰 글자 / Mint 800 (기본 버튼)      | 5.06:1           | AA                          |
| 흰 글자 / Navy (구매 버튼)          | 12.88:1          | AA                          |
| 흰 글자 / 위험 버튼 `#CD4656`       | 4.56:1           | AA                          |
| `#10162E` / ON 그라데이션 양 끝     | 13.06:1, 12.18:1 | AA                          |
| `#10162E` / Lime 500 ("무료" 배지)  | 13.06:1          | AA                          |
| `--gray-80` / 흰 바탕 (메타 글자)   | 5.94:1           | AA                          |
| `--text-tertiary` / 흰 바탕         | 3.10:1           | 본문 불가, 큰 글자·비활성만 |
| 흰 아이콘 / 카테고리 8색            | 3.08 ~ 3.44:1    | 그래픽 3:1 통과             |

- 누를 수 있는 것은 44×44px 이상이다. 칩·작은 버튼처럼 보이는 크기가 작으면 바깥 여백으로 채운다.
- 글자를 200%까지 키워도 내용이 잘리지 않는다. 화면 확대를 막지 않는다 (4.4).
- 초점 표시는 `outline: 2px solid var(--primary-color); outline-offset: 2px`다. 마우스 클릭에는 보이지 않게 `:focus-visible`에만 건다.
- 모달과 시트는 `role="dialog"` + `aria-modal="true"`로 알리고, 열면 제목으로 초점을 옮기고, 닫으면 연 버튼으로 돌려준다. Esc로 닫는다 (IA R12).
- 처리 중 화면 문구는 `aria-live="polite"`로 읽힌다.

## 11. 문구

- 해요체를 쓴다: "쿠폰을 발급하고 있어요", "지금 받을 수 없어요".
- 노출 문구에 줄표(—) 부연을 쓰지 않는다 (저장소 규칙). 쉼표를 쓰거나 두 문장으로 나눈다.
- 유료 쿠폰은 "환불", 무료 쿠폰은 "쿠폰 취소"로 나눠 쓴다 (PRD 6.5).
- 버튼에는 행동을 쓴다: [무료로 받기], [구매하기], [내 쿠폰에서 보기]. "확인" 한 단어로 끝내지 않는다.
- 금액은 `toLocaleString('ko-KR')` + "원"(예: 12,000원)으로 쓴다. 날짜는 Asia/Seoul 기준 `2026.10.19` 형식이다.
